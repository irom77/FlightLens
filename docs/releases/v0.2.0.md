# FlightLens 0.2.0

FlightLens now reopens the previous workspace and makes it easier to identify
which craft and flight controller a backup describes.

## What changed

- Reopen the backups that were open at shutdown and return to the previously
  active document. Files are read again from disk; moved or deleted files are
  reported and removed from the saved list.
- Show the flashed board target next to the firmware version when the backup
  includes `board_name`.
- Show craft and pilot names when available. Craft names in Betaflight 4.2 and
  4.3 comment headers now also appear correctly in the OSD preview.
- Document the release policy: compatible fixes use patches, new capabilities
  use minor releases, and patch counts have no limit.

## Upgrade and compatibility

No breaking changes are known. Install over the previous version; no manual
migration is required. This is a minor release because workspace reopening adds
new functionality.

The saved workspace contains local file paths, and the active document is
remembered separately. Backup contents are not saved in the session or modified.
Reopened backups reflect their current contents on disk, not a historical
snapshot. The saved list is local to this installation; portable `.flightlens`
session files remain planned. Earlier versions do not provide this reopening
feature.

Bundled firmware support remains Betaflight 4.2–4.5, with the existing verified
release restrictions for default recovery. Bundled firmware data and documented
export formats are unchanged. Analysis remains offline and source backups remain
read-only.

## Known limitations

- Identical backups opened from different paths share one document. Closing it
  can leave another path in the saved list, causing it to reopen at the next
  launch.
- Workspace reopening depends on the original local paths remaining accessible.
- Missing or unsupported values remain unknown; inspection and exports do not
  certify that an aircraft is flight-ready.
- Windows and macOS installers remain unsigned.
