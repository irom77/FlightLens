## What is already right

Worth stating, because several of the findings below are small next to it.

- **The desktop security posture is tight.** Strict CSP with no remote origins,
  capabilities limited to `core:default` + `dialog:default`, no filesystem or
  shell plugin, and every path grant originating in Rust from a native dialog,
  a drop event, or a canonicalized entry inside a native-granted workspace root.
  `WorkspaceIndex::path` re-canonicalizes and re-checks root containment on
  every resolve, and symlinks are skipped during discovery.
- **Originals are genuinely never overwritten.** Every write path uses
  `OpenOptions::create_new(true)`.
- **Portable session opening is not a blind grant.** A native dialog lists every
  reference before anything is read, and each backup must match its recorded
  SHA-256 or it is reported rather than opened.
- **Redaction is an explicit key list with a written rationale**, and it covers
  the renamed spellings across 4.2–4.5 rather than only the newest.
- **The "honest about uncertainty" claim holds in the code**, not just the
  README: `derive_defaults` refuses to read back a reset value unless the exact
  release is in the pack's verified list, and says why in a diagnostic.

## A. Defects

### A1 — Throttle preview is unavailable on most 4.2/4.3/4.4 patch releases

`crates/flightlens-core/src/throttle.rs:26-41` gates the preview on a literal
release list: `4.2.0`, `4.3.0`, `4.3.2`, `4.4.0`, `4.5.0`–`4.5.5`, plus two
vendor builds. The 4.5 line is covered patch by patch; the older lines are not.
Corpus files on `4.4.2`, `4.4.3` and `4.3.1` therefore report "not verified for
this firmware release or schema pack" even though they match a bundled schema
pack and are official releases.

This is the gate working as designed — the release list is per-release on
purpose — so the work is verification, not a code fix: run the existing upstream
differential fixture generator against the remaining patch tags on the 4.2, 4.3
and 4.4 lines and extend the list with whatever it proves. Consider moving the
list out of the match arm and into a pack field, so extending coverage becomes a
compatibility-data change rather than a core edit.

Impact: `4.4.x` is one of the most widely flashed lines in the wild, and the
Rate Profile tab's second graph is simply absent for it.

### A2 — Audit reference URLs are built from the declared version, so vendor builds get a dead tag

`crates/flightlens-core/src/analysis.rs:279-298`:

```rust
let version = d.firmware.version.as_deref().unwrap_or("4.5.0");
// ...
reference: format!("{source}{version}/src/main/{file}"),
```

`d.firmware.version` preserves the full declared identity, including suffixes —
`4.5.3.KAACK_V19`, `2025.12.3-alpha.KAACK_V19`. Neither is a Betaflight git tag,
so the URL 404s. The `unwrap_or("4.5.0")` branch is worse in kind: it names a
firmware version the document never declared.

The URL is currently only a `title` tooltip (`src/App.tsx:1224-1227`), so nobody
lands on the 404 by clicking, which is why this is low severity rather than
medium. Fix: build the tag from the matched pack (`pack.version`) and label it as
the certified schema line rather than the file's declared version — that is what
the rule was actually evaluated against. Drop the `"4.5.0"` fallback and omit the
reference when no pack matched, matching the `not_applicable` status the rule
already carries in that case.

### A3 — A feedback report can be unfilable with an error that tells the reporter to do what they already did

`crates/flightlens-core/src/feedback.rs:430-434`. `problems()` bounds the
description at `BODY_LIMIT` (2 000 characters). `build_report` then
percent-encodes the assembled body and rejects the result above `URL_LIMIT`
(8 000 bytes) with:

> This report is too long to prefill. Shorten the description to under 2000 characters.

For a description already under 2 000 characters, that instruction is satisfied
and the report still cannot be filed. `encode()` emits three characters per byte
for everything outside the unreserved set, so a Cyrillic or CJK description
expands roughly 9× — around 700 characters is enough to exceed the URL limit with
nothing the reporter can act on.

Fix: derive the message from the actual remaining budget ("shorten the
description by about N characters"), or — better — treat an over-long body the
same way an over-long configuration is already treated: put it on the clipboard
with instructions to paste, instead of refusing.

### A4 — The feedback dialog rebuilds the whole report on every keystroke

`src/Feedback.tsx:59-79`. The effect's dependencies include `subject` and
`body`, so each typed character invokes `feedback_report`. With a configuration
attached, that re-runs redaction across the entire document in Rust and ships the
complete redacted text back across IPC — up to the 16 MiB import limit — for
every keypress.

Fix: debounce (~250 ms), or split field validation (cheap, live) from preview
construction (expensive, on blur or on an explicit "Prepare preview" action).
The preview-must-match-submission invariant added in 0.10.x still holds either
way, since the submission rebuilds the report in Rust regardless.

### A5 — `SourceRegistry.files` grows for the life of the process

`crates/flightlens-core/src/source.rs:22-40`. `register()` allocates a fresh
`source-N` on every pick, drop, session restore and workspace open, and nothing
ever removes one: `forget_document` prunes `documents` and the saved session, but
not `files`. Registering the same canonical path twice also produces two ids for
one file.

Small in absolute terms, but it is the only unbounded structure in a code base
that carefully bounds everything else (32 documents, 128 MiB, 10 000 entries,
100 000 visits, 64 levels, 256-file batches). Fix: return the existing id when
the canonical path is already registered, and drop the `files` entry in
`forget_document`.

### A6 — `WorkspaceIndex::page` does not snap a caller offset to the page stride

`crates/flightlens-core/src/workspace.rs:162`:

```rust
let offset = offset.min(matching.len().saturating_sub(1) / 50 * 50);
```

This clamps the ceiling but passes any value below it through unchanged, so
`page(q, 37)` returns a window overlapping the previous page. Latent only —
`WorkspaceExplorer` sends multiples of 50 — but the command is reachable from the
renderer, and every other IPC boundary in this code base normalizes its input
rather than trusting it. Fix: `offset - offset % 50` after the clamp.

## B. Tooling and process

### B1 — There is no JavaScript/TypeScript linter

`src/App.tsx:153` carries `// eslint-disable-next-line react-hooks/exhaustive-deps`,
but ESLint is not in `package.json` and never runs. The suppression is inert, and
the `react-hooks` rules that would catch stale-closure and missing-dependency
bugs have never been applied to this frontend. Adding `eslint` +
`eslint-plugin-react-hooks` is a contained change that would flag A4 on the spot.

Recommended as the highest value-per-effort item in this document.

### B2 — `cargo clippy` runs nowhere

It passes clean today with default lints (verified in this review), which makes
now the cheapest possible moment to wire
`cargo clippy --workspace --all-targets -- -D warnings` into `test.sh` and both
release workflows. Adding it later, after drift, costs a cleanup pass first.

### B3 — CI only runs on `v*` tags — reinforces the existing TODO item

Already tracked under "Add free security checks, release gating and status
badges to CI", and this review supports raising its priority. Two points worth
adding to that item:

- The release workflows are currently the *only* CI. A commit that breaks the
  build on `main` is discovered when a release is attempted.
- Neither workflow runs `cargo fmt --check` nor the corpus check, so the
  release-gate checks are a strict subset of `./test.sh`.

### B4 — `pnpm format:check` now fails on three files, not two

TODO records `src/App.tsx` and `tests/inspector.spec.ts`;
`tests/throttle-comparison.spec.ts` has since joined them. The drift is the
argument for resolving it: a check that is always red stops being read. Recommend
the "reformat in a commit of its own" option already written in TODO, taken soon
rather than later.

## C. Architecture and maintainability

### C1 — `src/App.tsx` is 1 733 lines

It holds `App`, `Inspector`, `Osd`, `Filters`, `Export`, `ParameterTable`,
`DerivedTable`, `Empty`, `BackupInstructions` and `MissingSettingsNotice`. The
comparison half of the app is already one file per concern — `Comparison.tsx`,
`ParameterComparison.tsx`, `PortComparison.tsx` and so on, none over 300 lines —
so the inspector half is the outlier, not the convention. Splitting `Inspector`
and its tab bodies out would follow a pattern the repository already has, and
would incidentally shrink the prettier diff in B4.

### C2 — Every document is held twice and crosses IPC in full

`AppState.documents` keeps the parsed `ConfigDocument` in Rust (bounded at 32
documents / 128 MiB), and `App.tsx`'s `repository` ref keeps the deserialized
`Artifact` — including the complete `syntax` array with every raw line — in the
webview. A 16 MiB dump is serialized in its entirety across IPC on open, even
though the Raw tab paginates at 500 lines and no other tab reads `syntax`
directly.

Consider returning a document summary from `open_source` and adding a
`raw_page(config_id, offset, count)` command for the Raw tab and the source-line
jump. This is a design note, not a reported problem — no measurement in this
review showed it hurting.

### C3 — `repository` as a ref plus a revision counter

`src/App.tsx:49-51` and the bare `void revision;` at line 156 work around React's
render model rather than using it. Zustand is already a dependency and already
holds the document metadata; the artifact map could live beside it. Low priority,
but it is the one place in the frontend where the mechanism is visible in the
code.

## D. Product and coverage

### D1 — PID values are empty in almost every corpus backup

The corpus run reports `pid=0/4` and `WARN PID coverage: no known PID values in
any discovered profile` on the large majority of files, with only
`complete_pid_profiles=23` out of `pid_profiles_with_values=104`.

The cause is deliberate and documented: `Defaults` certifies only
`PG_CONTROL_RATE_PROFILES`, and `derive_defaults`
(`crates/flightlens-core/src/parser.rs:50`) iterates rate profiles alone. A
`diff`-based backup omits unchanged PID values, and FlightLens correctly refuses
to invent them.

Extending the verified reset table to `PG_PID_PROFILE`, on the same evidence
standard already used for rate profiles, is the single largest inspection
coverage win available and is not currently in TODO. It would light up the PID
tab for the diff backups that make up most real-world files. The existing
`tools/build_compatibility.py` pipeline and the "proven identical at every patch
release on the line" bar apply unchanged; the work is the verification pass, and
the comment on `Defaults` already says why it has not been done.

### D2 — Vendor builds render an empty Rates tab

Every `4.5.3.KAACK_V19` file in the corpus reports `rates=0/4 derived=0`, because
`defaults_certified()` requires an exact match in the pack's verified-release
list and a vendor suffix can never match. The reasoning is sound and the app
explains itself through `derived_note` and an `info` diagnostic, so this is not a
defect — but it is worth an explicit product decision, because it is the state
the most recent backups in the local corpus are in.

Two directions, both compatible with the project's stated principles:

- An opt-in, per-document "read back 4.5 reset values for this unverified build"
  control, with the derived values labelled as unverified everywhere they appear
  and excluded from export exactly as derived values already are.
- A verification path for specific vendor builds, the way
  `2025.12.3-alpha.KAACK_V19` is already enumerated in the throttle gate.

Doing neither is also a defensible answer; what is worth avoiding is leaving it
implicit.

### D3 — `mode_name` covers 19 box IDs; the rest render as "Mode ID 37"

`crates/flightlens-core/src/parser.rs:673`. Several modes pilots actually
assign fall outside the table and show as a bare numeric id in the Modes tab and
in the mode comparison. Betaflight's `boxId_e` values are permanent by design,
so filling out the table is low-risk — but it still needs the same per-line
source verification the rest of this project applies, since which ids exist
varies by firmware line even when their meanings do not.

### D4 — Save dialog, then a refusal to overwrite, is a confusing two-step

`src-tauri/src/main.rs` (`save_snippet`) and `src-tauri/src/portable.rs`
(`save_portable_session`) both open a native save dialog and then refuse with
`create_new(true)`. A user who selects an existing file and confirms the
operating system's own "replace?" prompt is then told "Choose a new filename.
Existing files are never overwritten."

The refusal is right; the sequencing is not. Suggest pre-seeding a
non-colliding default filename, and on `ErrorKind::AlreadyExists` reopening the
dialog with the explanation attached rather than dropping the user back to the
main window with an error banner.

## E. Accessibility

### E1 — Modals do not trap or restore focus

The paste dialog (`src/App.tsx:449+`) and the feedback dialog both declare
`role="dialog"` and `aria-modal="true"`, but Tab moves out of the dialog into the
page behind it, and closing the dialog does not return focus to the control that
opened it. Escape closes the paste dialog only, through the global keydown
handler; the feedback dialog has no Escape path.

### E2 — Plot values are mouse-only

`src/Plots.tsx:39-56` drives the hover readout from `onMouseMove` /
`onMouseLeave`. The SVG's `aria-label` describes the chart well, but the per-point
values in the legend are unreachable by keyboard and by touch. Suggest pointer
events plus a focusable plot with arrow-key scrubbing, or — cheaper and arguably
more useful for a bench tool — a value table behind a `<details>` element.

### E3 — `theme-color` is fixed dark

`index.html:6` declares `#10181c` regardless of the selected theme. Trivial;
listed only because the light theme is otherwise carried through consistently.
